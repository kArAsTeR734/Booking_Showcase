# Booking_Showcase

`npm run dev` запускает приложение.

`npm run storybook` запускает Storybook на порту 6006. `npm run build-storybook`
собирает статическую версию в `storybook-static/`.

`npm run check` запускает линтеры, проверку форматирования, тесты и сборку.

## Структура UI

В каждом сегменте `ui` у компонента своя папка в kebab-case. Храни рядом файл компонента, его стили, stories и тесты.
Пример структуры — `src/entities/booking/ui/booking-history-card/`.

## Локальный HTTP-мок

В режиме `npm run dev` мок доступен по адресу `http://localhost:3000/api/mock`. В `npm run start` доступна публичная выдача
`GET /api/mock/products` и `GET /api/mock/products/{id}`. Сессии и брони хранятся в памяти процесса и сбрасываются при перезапуске. Наличие в каталоге
задано тестовыми данными.

| Метод и путь относительно `/api/mock` | Действие                                                                                                       |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `GET /products`                       | Каталог. Параметры `category`, `minPrice`, `maxPrice`, `available=true`, `sort=price-asc\|price-desc`, `page`. |
| `GET /products/{id}`                  | Карточка товара, например `tent` или `sup`.                                                                    |
| `POST /session/login`                 | Создать тестовую сессию и получить `token` и учебного `user`.                                                  |
| `POST /session/refresh`               | Проверить токен и получить `token` и `user`.                                                                   |
| `POST /bookings`                      | Создать бронь. Передай `Idempotency-Key` и JSON `{"items":[{"productId":"tent","quantity":1}]}`.               |
| `POST /bookings/{id}/payment`         | Имитировать оплату существующей брони.                                                                         |
| `GET /bookings`                       | Получить оплаченные брони текущей сессии.                                                                      |

Для обновления сессии, бронирования, оплаты и истории передавай `Authorization: Bearer <token>`.
Для воспроизведения ошибки добавь к запросу заголовок `X-Mock-Scenario` с нужным значением.

| Значение                | Где срабатывает                | Ответ                                                                                         |
| ----------------------- | ------------------------------ | --------------------------------------------------------------------------------------------- |
| `expired-session`       | Бронирование, оплата, история  | `401 SESSION_EXPIRED`.                                                                        |
| `availability-conflict` | Создание новой брони           | `409 AVAILABILITY_CONFLICT` с `unavailableProductIds`. Первая позиция помечается недоступной. |
| `payment-failed`        | Оплата ещё не оплаченной брони | `402 PAYMENT_FAILED`.                                                                         |

Чтобы повторить действие после имитации ошибки, убери заголовок сценария. При повторе создания той же брони используй тот же ключ и состав заказа. При повторе оплаты используй тот же номер брони из поля `id`.

Токен хранится в sessionStorage и проверяется при открытии сайта. Учебный профиль восстанавливается из ответа мока. При 401 токен удаляется, при транспортном сбое проверку можно повторить.

## Каталог

На `/` сервер проверяет дату, фильтры, сортировку и страницу из URL, запрашивает список через TanStack Query и рендерит
заголовки, карточки с ценами и ссылки. HTTP-запрос идёт на локальный `/api/mock/products` того же процесса Next.js.
Клиент получает применённые параметры и число результатов для контролов. Период и фильтры редактируются на клиенте.
При навигации по URL сервер возвращает следующую выдачу, а пока запрос выполняется, предыдущая остаётся видимой.
Черновик фильтров сохраняется при смене периода, сортировки и страницы, пока применённые фильтры совпадают.
Для нового черновика форма запрашивает `total` через тот же каталог с задержкой 250 мс. Число у «Показать» учитывает
все поля черновика. У категории указано количество доступных позиций в ней по всему каталогу. Мок сообщает доступность
позиции без складских остатков.

Публичный вход `@/entities/catalog/index.server` предоставляет загрузчик только серверным модулям Next.js. Клиентские
компоненты используют `@/entities/catalog` для типов и операций над параметрами каталога.

| Слой         | Ответственность в каталоге                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `pages/home` | Композиция экрана, разбор входного URL и подготовка ответа API для выдачи.                         |
| `widgets`    | Навигация проката, панель управления каталогом и серверный блок выдачи с пагинацией и состояниями. |
| `features`   | Действия выбора периода, применения фильтров и сортировки.                                         |
| `entities`   | Запрос каталога и модель параметров в `catalog`, карточка товара в `product`.                      |

Период задаётся через `start` и `end` в формате `YYYY-MM-DD`. По умолчанию используется текущая дата по Волгограду и
дата через три дня. При некорректном диапазоне применяется тот же период с пояснением. Возврат должен быть позже выдачи.
Мок фильтрует по одной категории, цене и признаку наличия. Даты сохраняются в ссылке для выбора периода, а наличие
показывается по булевому значению из ответа мока.

Адреса переходов объявлены в `src/shared/const/routes.ts`.

Гость перенаправляется на `/auth` при запросе истории броней. Для корзины и условий выдачи вход не требуется.
В этой версии у корзины, условий выдачи и истории есть точки перехода, сами страницы ещё не реализованы.

## Карточка товара

`GET /api/mock/products/{id}` возвращает поля товара из каталога, массив `characteristics` с полями `label` и `value` и
`pickupAddress`. Неизвестный идентификатор возвращает `404 NOT_FOUND`. Наличие задаётся полем `available` и не зависит
от периода. Публичное чтение карточки работает в development и production; остальные операции мока в production закрыты.

На `/product/[id]` сервер проверяет ответ мока и определяет отсутствие товара до начала отправки страницы, сохраняя
HTTP 404. В клиентский компонент передаются проверенные сведения товара и применённый период. Изменение периода,
поделиться ссылкой и добавление в корзину выполняются на клиенте. Корзина хранит единый период и количество позиций
в `sessionStorage` текущей вкладки; на странице показывается только её счётчик.
